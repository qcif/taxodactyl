# `nf-test` Automated Continuous Integration Testing

The `nf-test.yml` continuous integration testing workflow is designed to identify discrepancies between current test runs and established baselines. It uses `test/core`, a small, diverse set of samples. 

Actions can only return either success or failure. This workflow is designed to return a failure if any of the tests error or return discrepancies. 

## Workflow action

- The `nf-test.yml` workflow is designed to run on both:
	- GitHub-hosted runner: `ubuntu-latest`
	- self-hosted runner: 4C/8G, 25GB+ disk free
- If one test fails the other will continue, due to `fail-fast: false` setting. 

- It is currently set to run:
	- scheduled weekly, 
	- on push for selected branches, 
	- on pull requests for `main`, or;
	- on manual trigger.

- All runs are intended to be ephemeral, but an archive of runs is saved on the SH runner to allow for easy error investigation. 

- All test steps are set to run, even if `nf-test` returns a failure. 

## 1. nf-test

The workflow sets up all dependencies and runs `nf-test` on the `core` test scenario. 

- **How it works:** `nf-test` runs the complete Nextflow pipeline and tests a number of assertions, including snapshots of workflow outputs and expected number of output files. 

- **Baseline snapshot**: The test snapshot was generated by running the `core` test set against frozen refdata, which are downloaded to run the workflow. 
	- For more information on the current version of the `core` test scenario and how to download the frozen test refdata, see `test/core/README.md`.

- **Conditions for failure**: If Nextflow run fails, or if any assertions of `nf-test` fail, this step and a "Run failed" notification will be sent from GitHub.

- **Artifacts:** 
	- Nextflow run failures prompt `trace.csv`to be printed to the console.
	- Discrepancies are summarised in `nf-test_errors_summary.csv` using the `diff_json_snapshot_to_csv.py` utility script. 
		- This summary is printed to the console to view from GH UI and is included in the saved files on the SH runner. It is not uploaded to GH as an artifact. 
	- Both `trace.csv` and `nf-test_errors_summary.csv` are parsed using `collect_artifacts.py` and all work directories for steps with failed/aborted Nextflow steps or discrepancies are copied to a folder called `collected_errors` which is:
		- uploaded as an artifact on GH runner, or;
		- archived under the test run on the SH runner. 

## 2. Flags

The workflow then compares expected report flags for the `core` test scenario (`/test/core/flags`) against the flags reported in the test run. 

- **How it works:** Workflow step `Test flags` runs `/bin/collect_flags.sh` on the test run and `/bin/test_flags.py` to compare collected flags with the expected flags. 

- **Baseline flags**: These are added/updated at the same time as `nf-test` snapshots per above. 

- **Conditions for failure**: This step returns and error and prompts workflow failure notification only if `test_flags.py` errors or fails, which occurs if there is a difference in any flags or files. 

- **Artifacts:** Discrepancies are summarised in `flags_errors.txt` and `flags_results.txt`:
	- Both logs are printed to the console to view from GH UI and is included in the saved files on the SH runner. They are not uploaded to GH as an artifact. 
	- `flags_results.txt` is parsed using `collect_artifacts.py` and all work directories for steps with discrepancies are copied to a folder called `collected_errors` which is:
		- uploaded as an artifact on GH runner, or;
		- archived under the test run on the SH runner. 

## 3. pytest Selenium 

HTML reports generated by the Nextflow run are tested using the Selenium pytest suite. 

- **How it works:** Workflow step `Soft link reports for pytest` collects all HTML reports from the test directory to pass to `pytest test_reports.py` in the `Install and run pytest` step. `./testkit.py render` then generates a summary report from the testing. 

- **Baseline reports**: Reports and extracted assertion values from the baseline reports are saved to the repository at `/test/selenium/expected/`. 

- **Conditions for failure**: If `test_reports.py` returns a failed test, this step fails and returns a workflow failure notification. 

- **Artifacts:** Discrepancies are summarised in the `review.html` summary report:
	- `review.html` is uploaded as a GH artifact on both GH and SH runs. 
	- `review.html` is also copied from it's default location in the repo to the test run folder, which is then archived on the SH runner for inspection.
