### SR-7b7f33037804-001 — Coverage-only mode has no complete spec contract

- Spec: `spec/nextflow/workflow.md:31` (NF-WF-001) requires the sequence workflow;
  `spec/python/p5-db-coverage.md:31` and `spec/python/p6-report.md:18` describe
  sequence/metadata arguments as required. `spec/contracts/outputs.md` describes
  per-sample reports, not the combined coverage-only report.
- Code: `main.nf:45` selects `TAXODACTYL_COVERAGE` for `coverage_taxa`.
  `workflows/coverage.nf:17` validates taxa without sequences, assesses coverage,
  and combines results into one report. `nextflow_schema.json:40` defines the input.
- Origin: `ef96c8f`, PR #323.
- Why it matters: following the spec would miss an implemented operating mode,
  its different inputs, report layout and failure behavior. The constitution's
  spec-before-code rule (`CONSTITUTION.md:265`) requires matching spec updates.
  Critical denotes this governance conflict, not a demonstrated runtime failure.
- Options: document the mode if intended; identify implementation changes if the
  existing sequence-only requirements are intended; reconcile both if necessary.
- User decision: pending. Decision evidence: none. Resolution: open.
